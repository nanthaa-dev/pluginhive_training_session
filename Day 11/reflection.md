# Day 11 reflection

I chose to put the field label, hint, and error rendering in a shared `FieldShell`, then use it from both the text inputs and the delivery-note textarea. That keeps the markup consistent and makes the label-to-control relationship and `aria-describedby` behavior easier to maintain. The note limit is stored once and reused by validation, the hint, and the fake API. I also delay showing client validation until the first submit so the form does not report errors while someone is still entering their details. Failed requests keep the values and the same idempotency key, which lets a retry safely represent the same order attempt.

One remaining weakness is that the current order service does not store delivery notes. To complete this assignment without changing the existing API contract or database, the form uses an in-memory Module 5-style fake API. It supports the note validation and idempotency behavior for the demonstration, but its orders disappear on reload and are not visible to other clients. A production version should add the optional note to the real API, its validation and persistence layer, and integration tests before replacing the fake implementation.
